国内外连通

查询后自动测

查出一个公网 IP 之后，这里同时看 ICMP（ping）和一个 TCP 端口，默认 22（SSH）。国外连得上、国内连不上，按这个口径视为在大陆被墙或被封。两边都不通，更像是机器没开、这个端口没在监听，或防火墙把探测丢掉了。家宽和很多服务器本来就没开 22，两边都不通不等于网断了。

    浏览器暴露自查

    按需运行

    挂 VPN 的人最该看这一格：WebRTC 有时会绕过代理，直接把你真实的出口地址交出去；现代浏览器的 mDNS 混淆则会把内网地址换成随机主机名。下面的探测只有你点了才会跑。

    • 只有 .local 主机名：mDNS 混淆生效，这是现代浏览器该有的样子，不是泄露。
    • 漏出内网地址：别人能看到你的局域网网段，足够推测你在公司还是在家。
    • 公网地址与当前出口不一致：代理没兜住真实出口，这一种最该处理。

    探测用的 STUN 节点是 Cloudflare 的公开服务，只用来拿到你这一侧的公网反射地址；结果留在页面上，不回传本站、不写日志。

    数据与限制

    • 归属地精度来自第三方公开地理数据，国家级可靠，城市级为近似值，机房与移动网络出口尤其容易偏。
    • 你自己的信息优先由边缘节点从连接里直接读取；该能力需要站点部署在支持边缘函数的环境，纯静态预览时会自动回退到公开接口。
    • 速率限制由上游公开接口决定，单次批量最多 20 个，连续大批量可能返回失败，稍等再试即可。
    • 服务端不落库：本站没有数据库，不保存查询记录。浏览器里的历史记录存在你本机的 localStorage，可一键清除。
    • 风险判定是启发式规则，用于帮助你判断「这是家宽还是机房」，不构成安全结论。
    • 连通性只看此刻从若干公开节点出发，能不能 ping 通、以及指定的 TCP 端口能不能连上。国外通而国内不通，才按「被墙 / 被封」来读；两边都不通，先怀疑机器或端口本身。节点离线不算失败。探测有速率限制，太密集会被要求稍后再试。

    常见问题

    怎么查看我自己的 IP 地址和归属地？

    打开本站即自动完成：右上「你的网络体检」会显示你的公网 IP、所在国家与城市、运营商与 ASN、协议版本与 TLS 版本。部署在支持边缘函数的环境时，这些数据直接从你的连接里读取，不经过任何第三方接口；纯静态环境下会自动回退到公开地理数据接口，并在卡片右上角如实标注当前来源。

    可以查网站域名的 IP 吗？

    可以，输入框同时接受 IP 与网站域名。输入 example.com、https://example.com/path 甚至中文域名都可以：程序会先剥掉协议、路径与端口，把中文域名转成 punycode，再通过 DNS-over-HTTPS 向公共解析服务查询 A 与 AAAA 记录，拿到地址后继续做归属地、ASN 与风险信号分析。一个域名常常解析出多个地址（CDN 尤其如此），解析框会列出全部地址与 TTL、CNAME 链，点任意一个即可切换分析对象。域名解析在浏览器里直连完成，不经过本站服务器。

    IP 归属地是怎么查出来的？准不准？

    IP 到地理位置的映射来自各网络运营商登记的地址分配块与网络测量数据，由公开地理数据库汇总提供。本站依次尝试多个数据源，任一超时或限流就自动换下一个，并在结果里标明这次是哪一个返回的。国家级结果可靠，城市级是近似值——机房出口、移动网络与共享出口尤其容易偏几十到几百公里。遇到国家和经纬度打架时，以地图上的落点为准。

    为什么查出来的城市跟我实际所在地不一样？

    常见原因有三个：你走的是运营商的集中出口（城域网出口常常不在你所在城市）；你开了代理、VPN 或走了云服务商的网络节点；或者你所在的网络使用共享地址（CGNAT）。这三种情况下查到的都是出口路由器的位置，而不是你设备的物理位置。

    IPv4 和 IPv6 都能查吗？

    都能。输入框自动识别两种格式，例如 8.8.8.8 与 2001:4860:4860::8888，也接受 ::ffff:1.2.3.4 这类内嵌 IPv4 的写法。结果卡还会给出该地址的十进制整数、完整展开形式、所在网段（IPv4 的 /24 或 IPv6 的 /64）以及反向解析域名。IPv6 的地理覆盖普遍弱于 IPv4，界面会额外提示置信度较低。

    怎么算一个网段包含哪些地址？

    用「子网 / CIDR 计算器」那一格，输入 10.0.0.0/22 或 2001:db8::/48 这样的写法，立刻给出网络地址、广播地址、子网掩码、通配符掩码、可用主机范围与地址总数。全部在浏览器里算，不发任何请求。结果卡里「所在网段」那行是个按钮，点一下会把当前查询 IP 的 /24 或 /64 直接带进计算器。

    查域名时为什么没有 IP，却有 MX 和 TXT 记录？

    因为那类域名本来就不用来提供网站，只用来收发邮件。查询域名时程序会并行取 A、AAAA、MX、TXT、NS、CAA，外加 _dmarc；如果一个地址都没有、但有其他记录，界面会直接摊开记录清单而不是报解析失败，并顺手做一次邮件配置体检。

    挂着 VPN，WebRTC 会不会暴露我的真实 IP？

    有可能。WebRTC 为了建立点对点连接，会去收集本机的网络候选地址。「浏览器暴露自查」分两轮：第一轮不配 STUN，只看内网地址有没有漏出来；第二轮用 Cloudflare 的公开 STUN 节点拿公网反射地址，再跟你当前的出口 IP 比对。现代浏览器默认启用 mDNS 混淆，把内网地址换成随机 .local 主机名，那属于保护生效而不是泄露。探测只有你点了才会跑，结果不回传本站。

    怎么看一个 IP 在国内是不是被墙？

    查完这个地址后，页面会自动测 ICMP，以及一个 TCP 端口（默认 22，可以改成 80、443 或其他）。国内节点连不上、国外节点连得上，就按「这个端口在大陆被封」来读。两边都通，则这个端口不像被墙。两边都不通，更像是机器没开、端口没在监听，或防火墙把探测丢掉了，不一定是被墙。只 ping 通还不够：有的封锁会留着 ICMP，单封 TCP。香港和台湾的节点算在国外一侧。这是若干公开探针此刻的结果，不是一份官方封锁名单。

    怎么判断一个 IP 是机房还是家庭宽带？

    看「风险信号」这一格。它根据 ASN 归属与运营商关键词做启发式判定：命中云厂商或托管商会显著加分，命中移动运营商或住宅宽带则基本不加分，最终给出 0 到 100 分与四档结论。这只是判断线路性质的线索，不是实时威胁情报，也不能证明某个地址在做坏事。

    可以批量查询多个 IP 吗？

    可以。把多个地址用换行、逗号或空格分隔粘贴进「批量查询」，一次最多 20 个，两路并发逐个解析，结果表格给出位置、ASN 与运营商、线路性质与数据来源，可一键导出 CSV。

    可以在命令行里用 curl 查吗？

    可以，而且不需要密钥。curl -L 本站 只回一行纯文本 IP；curl -sL 本站/json 回完整 JSON，加 ?pretty 会格式化。判断依据是 User-Agent 与 Accept：curl、wget、httpie、PowerShell 会拿到纯文本，浏览器照常拿到完整界面。

    你们会记录我的查询内容或 IP 吗？

    本站没有数据库，服务端不保存任何查询记录，页面里也没有第三方统计或广告脚本。唯一的本地存储是「最近查询」列表，它保存在你自己浏览器的 localStorage 里，可以在「数据与限制」一格中一键清除。
