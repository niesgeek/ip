指纹是什么

没有一项需要你点同意。浏览器要正确显示网页，就得知道像素比、语言和自己支持哪些接口。网站把这些已经存在的事实收起来做成哈希，就可以在你换了 IP、清了 Cookie 之后，仍然看出是不是同一台环境。它不是存在你机器上的一个文件，所以也没有一个开关能把它「清掉」。

这一页最稳的是渲染那一组：同一套图形画出来的像素、WebGL 报出的参数、离线音频的几个样本、候选字体的宽度、若干盒子的布局尺寸。它们取决于显卡、驱动、字体和内核，不是一个可以随便勾选的偏好。

两次 ID 相同，只说明这些稳定项没变；ID 变了，也只说明其中某一项变了。要判断一个网站能不能认出你，还得看对方服务器上的数据。这一页做不到那件事。

这一页自己做了什么

  • 只请求本站已有的接口。采样时会 GET /api/whoami，和首页读你的连接是同一份实现。探针的取值不会放进这个请求，也不会发到别的域名。
  • 不申请权限。不调用摄像头、麦克风和定位。权限那一行只查询当前状态。响应头里也关掉了这三项，避免误弹窗。
  • 不留下结果。不写 Cookie，也不把指纹 ID 放进 localStorage。再测一次只和这一页内存里的上一轮比较，刷新就清掉。
  • 易变项不进 ID。窗口尺寸、存储已用量、网络类型估计会列出来，并按一半计入估算，但不会改掉指纹 ID。所以再测一次仍然有意义。

这一页明确不做的事。没有 JA3 / JA4：那要看 TLS Client Hello，/api/whoami 不返回这个字段，Cloudflare Pages 的免费环境通常也不提供。没有把同一套探针放进 iframe 或 Worker 再对一遍。没有实测的访客比例，上面的百分比是权重估算。

再测一次在比什么？

把全部信号再采一遍，和这一页里留着的上一轮逐项比较。变了的行会标出来，顶部会说明指纹 ID 变没变。窗口大小这类易变项变了而 ID 没变，是预期结果。这只是同一台设备的两次快照，不能证明某个网站会把你认成同一个人。

为什么有的项是「未提供」或「被拦住」？

未提供表示这个浏览器没有那个接口，例如不少浏览器不实现 navigator.userAgentData。被拦住表示接口在，但读的时候被拒绝。两种都不是页面坏了。「不给」本身也会进入指纹 ID，因为这也是一种差别。摄像头、麦克风和定位被本页的策略关掉，查询结果会写成站点策略拦住，不是你刚点了拒绝。

这和首页的浏览器暴露自查是什么关系？

首页那一格看的是 WebRTC 会不会绕过代理，把真实出口地址交出去，而且只有你点了才跑。这一页看的是设备侧已经公开的环境信号，打开就会采样。两边都不把结果上传。

撞车数字能不能当成统计？

不能。它假设各项互相独立，再按事先写好的权重换成一个数量级。真实用户的屏幕、内核和时区经常一起相同，所以实际相同的人会更多。本站没有访客库，不会出现「多少访问者里有几个和你一样」这种句子。
